# AGENTS.md — devlogs

Repo constraints from prior work here.

## Hard-won constraints

- **The interpreter is `python3` / `.venv/bin/python`; bare `python` is absent (exits 127).** Use the explicit interpreter in every verification command for this repo — a bare `python` silently no-ops a verification step (exit 127), and a 127/blank result must never be read as "tests passed."
- **`HOWTO-COLLECTOR.md` and `HOWTO-COLLECTOR-DEPLOY.md` are CRLF — patch them byte-wise or with the Edit tool, never `pathlib.write_text()` after `read_text()`.** `write_text` normalizes CRLF→LF and turns a 2-line change into a whole-file diff (breaking `git blame`, tripping lint). After any scripted file edit, check `git diff --stat`; a line count far larger than the intended change is a defect to revert.
- **Every `DEVLOGS_*` config key must have a consumer.** DL-006 itself was two settings parsed but never read. When adding a config knob, confirm it is referenced by a non-config module (a test over `config._DEVLOGS_CONFIG_KEYS` asserting each resulting attribute is read somewhere closes the class).
- **An OpenSearch text-mapped field cannot be aggregated/term-queried on the bare field — and handler-written fields + the index template are a paired surface.** `get_index_stats` once documented that application/component are text-mapped and avoided aggregating them, but `list_applications` later aggregated the bare field anyway (the work-around was never promoted to a mapping fix) — the recurrence vector. Any field the handler writes must have an explicit property (keyword, or `fields.keyword`) in `build_log_index_template`; when adding an aggregation/list, confirm the field is keyword-mapped. A test asserting (handler-written fields ⊆ template properties) fails fast on the next omission.
- **Enumerate release/publish targets from the publish scripts, not from RELEASING.md.** A version bump missed `devlogs-node` because the manifest list was read from RELEASING.md (which listed only pyproject + browser), but the real publish targets live in `publish/publish-npm.sh` (browser AND node) and `release.sh` never synced node — users `npm i devlogs-node` got a stale version mismatching the Python/browser packages, turning cross-package bugs into version-skew mysteries. A doc that summarizes a set the code actually defines is a candidate trap — verify against the scripts. A package-version drift test (all manifests in lockstep) catches the class at `pytest` time.
